# #191: fraction: [k] on backend/bostan_mori

2026-10-13, claude. Started on main `0d6a23e`.

`Fraction::operator[]` is now one call, `fps::bostan_mori::coefficient(p.span(), q.span(), k)`
(#114 r1, PR #187). The frontend's loop (two `f * g` per bit of k, `negate_odd`, `every_other`,
`cut`, fresh polynomials per step) is gone, and with it the include of `fps/modular.hpp`.

## What the frontend does

- Nothing but the call: the kernel cuts p and q to k + 1 words, drops p's zero top words, and
  handles an all-zero p (the old loop's `p.degree() < 0` exit). q[0] != 0 is still the
  constructor's check, so the kernel's own `std::domain_error` (empty q or q[0] = 0) cannot
  happen. `take(n)` is unchanged.
- Limits: past 2^23 words of values form the kernel falls back to its `products` variant
  (`ntt::multiply`, `std::length_error` past 2^25), as the old loop's `f * g` did. Not tested at
  that size (d = 2^22 would take seconds per call); the kernel's tests own it.
- Memory: the kernel keeps per-thread arrays for the thread's longest call (huge pages), so a
  [k] allocates only when it is longer than the thread's earlier ones. `test_threads` (4 threads,
  d = 3000 and Fibonacci) covers the per-thread state through the API.
