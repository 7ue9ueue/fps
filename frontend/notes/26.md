# #26: composition, compose and compositional_inverse

2026-10-12. `fps::compose(f, g, n)` (n defaults to max(`f.size()`, `g.size()`)) and
`fps::compositional_inverse(f, n)` (n defaults to `f.size()`) in `include/fps/composition.hpp`,
included from `fps/fps.hpp`. The prototype's `composition.hpp` wraps its private copy of lc-opt
(`fps/lcopt/composition.hpp`, `taylor_shift.hpp`), which stays there; the algorithms here are
written plainly on `raw::mul`, `middle_product`, `Factorials` and `detail::series`. Main at
6856d40 when started.

## What it does

- compose, with a = g[0], on g mod x^n (only that counts):
  - constant: f(a) (Horner, `Polynomial::operator()`), then zeros;
  - a + b x, b != 0: h[k] = F[k] b^k, F = f(y + a) (F = f for a = 0). The Taylor shift is one
    middle product: k! F[k] = sum_j (f[k + j] (k + j)!) (a^j / j!), for k < min(n, f.size()),
    of f weighted (zeros past f) by e = (a^j / j!) reversed, so a short n costs a cyclic product
    of f.size() + n - 1, not 2 f.size();
  - else f(g) = F(g - a), F mod x^n by the same Taylor shift, by Kinoshita and Li's algorithm
    (arXiv 2404.05177; read for the idea, written here from the derivation below).
- Kinoshita and Li, as written here: Q = 1 - y G(x), G = g - a, and
  f(G) = [y^(m-1)] f_rev(y) / Q mod x^n. 1 / Q = Q(-x, y) / V(x^2, y), V(x^2, y) = Q(x, y)
  Q(-x, y), so going down each level halves x (ceil) and doubles y's degree, n words per level;
  Q_l(0, y) = 1 at every level, as G[0] = 0. Going up, level l needs only the y-window
  [m - 2^l, m) of f_rev / Q_l, which is the window [m - 2^(l+1), m) of level l + 1 times
  Q_l(-x, y): a product cut in x, a middle product in y. At the bottom (one row) the window is f
  itself, reversed in a row of 2^L, so m never appears in the code. Every level is one product
  of Kronecker-packed bivariates on `raw::mul` (x^i y^j at word i Y + j, Y the y-length of the
  full product, cut to the rows): down, Y = 2 k + 1 (k = 2^l); up, Y = 3 k, the middle k words
  of each row kept.
- compositional_inverse: Kinoshita and Li's power projection, [x^N] f^k for k <= N = n - 1
  (Bostan and Mori on p / q, p = 1, q = 1 - y f, two products a step, q(0, y) = 1 so the base
  needs no inverse), then Lagrange: [x^j] (x / g)^N = N / (N - j) [x^N] f^(N - j). The factor N
  cancels once h is divided by h[0], so h[j] = [x^N] f^(N - j) / (N - j), and
  g / x = (1 / f[1]) (h / h[0])^(-1 / N) by `detail::series::power` (exp(e log), e = -1 / N mod P,
  which is exact below x^P). A mutation that dropped N showed it to be redundant.
- Preconditions: compositional_inverse reads f mod x^n only, as the series functions: f[0] = 0 for
  n >= 1, f[1] != 0 for n >= 2, n <= P (reciprocals 1 .. N and pow), else `std::domain_error`.
  DESIGN.md said "f[0] == 0, f[1] != 0" without n; now it says this. compose has none.
- Limits: `ntt::multiply` transforms the whole product of its factors, even one cut to fewer
  words, so two factors of S words need 2 S - 1 <= 2^25, S <= 2^24. Both functions compute every
  level's S first (`compose_longest`, `projection_longest`, O(log n)) and throw
  `std::length_error` before allocating if one passes 2^24. Both run up to n = 2^22 and throw
  from 2^22 + 1: there the last levels have 2 rows of y-length 3 2^22 (compose) or 2^23 + 1 (the
  power projection). compose with an empty f returns n zeros before the check (no product
  runs). The Taylor shift (`ntt::middle_product`, cyclic of f.size() + t - 1 words) checks that
  sum against 2^25 before its tables.
- Memory: compose keeps every level's Q_l, about (log2 n + 2) n words (2^20: 92 MB); lc-opt's
  version (#105) has the layout to do better.

## Tests (`frontend/test_composition.cpp`)

- compose against Horner mod x^n (schoolbook) for n in {0, 1, 2^k, 2^k +- 1} up to 65, with 26
  inner functions per n: 0, constants (with trailing zeros), x, b x, x + a, a + b x, -1 - x,
  a = 1 with b = 1 and with a general tail, a = -1, a + b x + c x^n (linear mod x^n), x^2,
  a + c x^2, random g of 3, n, n + 3 and random sizes, random / mostly zero / all P - 1, each with
  g[0] and with g[0] = 0; f of 0, 1, n - 1, n + 3, random sizes and all three kinds at n.
  Above 65, to 1025: f of 1-6 terms against the schoolbook, f of n + 3 against Horner on
  `fps::mul`.
- Default sizes; a constant g evaluates all of a long f; empty f.
- Identities at n = 2^14, 2^14 + 1, 100003: compose(exp series, g) = exp(g), compose(log(1 + y),
  g) = log(1 + g) (g[0] = 0); f = 1 + y + ... + y^(n-1) at g[0] != 0: f(g) (1 - g) = 1 - g^n;
  Taylor shift by a and back, scaling by b and back, a + b x and back; short n of a long f on
  the linear and the general path.
- compositional_inverse: f(g) = x and g(f) = x mod x^n on every edge size to 1025, f of 2, 3, n,
  n + 3 coefficients and the three kinds; x / (1 - x) gives x / (1 + x); x e^x gives Lambert's W,
  (-k)^(k-1) / k!, at n = 2000; both directions at 2^14, 2^14 + 1, 100003.
- 4 threads; every error: both preconditions at the n where they start to count, n > P; the
  length errors at 2^22 + 1 and 2^24, checked to come from the composition's own check (the
  message), not from `ntt::multiply` midway; the Taylor shift's on the linear path (f of
  2^24 + 1 words) and on the general path (f of 2^25 - 2^22 + 2 words, n = 2^22); an empty f at
  n = 2^24 (zeros, no error).
- At the limits (`test_limits`, -O2 only, skipped under ASan): compose at n = 2^22 (f = 1 + y:
  1 + g), compositional_inverse at n = 2^22 (x + x^2: signed Catalan numbers), and the Taylor
  shift's middle product at exactly 2^25 words (x^(2^24) shifted by 1, cut to 2^24: binomials).
  About 17 s of the test's 20 s on the Mac (M4, -O2).
- Mutations (15, scripted): 13 fail the test. The two that pass are no bugs: a constant g sent
  down the linear path (KL with G = 0 gives F(0) = f(a)) and the factor N above (now removed).
  One of the 13 (Taylor shift skipped for a = 1) passed at first; the inner functions now include
  a = 1 and a = -1.
- Pass at -O2 and ASan/UBSan on the Mac (scalar, arm), `lc-amd` (scalar, sse, avx2),
  `lc-intel-test` (avx512), `lc-zen5-test` (zen5) and `lc-arm` (arm).

## Review of PR #130, round 1 (three findings), and what changed

1. The size checks compared one factor's S with 2^25, but `ntt::multiply` limits the whole
   product (`bit_width(n + m - 2) <= 25`), so S <= 2^24: n = 2^22 + 1 to 2^23 passed the check
   and threw from inside the work (2^22 + 1 after 4.4 s on the Mac). The checks now compare S with
   2^24 (`kMaxFactor`), and the header says n <= 2^22 for both. Tests just past the limit (2^22 + 1,
   by the message) and at it (`test_limits`).
2. compose with an empty f returned zeros only after the length check; it now returns first.
3. The Taylor shift's own `std::length_error` has tests on both paths.
