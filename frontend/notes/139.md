# #139: points: evaluate, interpolate, to_newton_basis on backend/evaluation

2026-10-12, claude. Base `dedab27` (origin/main).

`include/fps/points.hpp` now makes each of `evaluate(f, points)`, `interpolate<P>(points, values)`
and `to_newton_basis(f, points)` one call into `backend/evaluation/evaluation.hpp` (#104, PR #135:
lc-opt's transposed descent on point trees with kept transforms), writing into the returned
memory. The frontend's own tree (`detail::points::Tree`, its descent by `fps/division.hpp`, the
leaf loops) is gone: 243 lines to 76.

- Checks kept in the API: points and values < P (`std::domain_error`; the kernel does not check
  words), `values.size() != points.size()` and too few points for `to_newton_basis`
  (`std::domain_error`, checked before the kernel, so its `std::invalid_argument` for sizes is
  never reached), 2^25 or more points to `interpolate` and `f.size() >= 2^25` to `to_newton_basis`
  (`std::length_error`, before any work; the kernel's own bound is `> 2^25`). A repeated point in
  `interpolate` is the kernel's `std::domain_error` (a zero M'(a_i), on its O(m^2) path up to 32
  points and on its tree). `to_newton_basis` passes the kernel only the n - 1 points it reads.
- Changed: `evaluate` has no size limit any more. The 2^25-point `std::length_error` was the
  frontend tree's (its root passed the NTT's 2^25); the kernel splits f and the points into chunks
  of 2^24. DESIGN.md's paragraph on errors now says so. The test that asked `evaluate` at 2^25
  points to throw now asks it to work at 2^25 + 1 points (f linear: Horner's rule on every target,
  cheap), and asks `interpolate` and `to_newton_basis` for the `std::length_error` instead. Every
  other test is unchanged, plus one repeat in one lane of the kernel's tree (indices 8 and 16 of
  1000); the comment on sizes now names the kernel's cut-offs.
- Tests: `kernel.py test frontend` passes (28 of 28, -O2 and ASan/UBSan) on the Mac (scalar, arm),
  `lc-amd` (scalar, sse, avx2), `lc-intel-test` (avx512), `lc-zen5-test` (zen5), `lc-arm` (arm).
  `test_points` alone on `lc-amd` scalar: 2.92 s at -O2, 9.19 s under ASan/UBSan (base: 2.98 s,
  11.13 s).
- Bench (`frontend/bench_points.cpp`): `<op>@kernel/<lg>` pairs on the same inputs into a kept
  output. `kernel.py bench frontend --filter '(evaluate|interpolate|newton)' --base dedab27`, 7
  rounds, GCC 15.2, n = m = 2^lg.
