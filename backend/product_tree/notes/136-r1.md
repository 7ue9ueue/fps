# #136 r1: base products of unit-term leaves (for backend/evaluation)

2026-10-16, claude (issue #136, round 1: backend/evaluation, its log
`backend/evaluation/notes/136-r1.md`). Base main e88390e. GCC 15.2 (the pinned image).

- `multiply_units` (kernels.hpp): `multiply_lanes` for factors whose constant term is 1 (kR in
  Montgomery form), as backend/evaluation's `1 - a x`: the terms a[0] b[t] = b[t] and a[t] b[0] =
  a[t] are added after the Montgomery step instead of multiplied, c[0] = kR; a pair of linear
  factors is one product, not four. Tested in `backend/evaluation/test_units.cpp` (every degree pair
  up to 8 x 8, against schoolbook).
- `LaneTree::coefficients` uses it when the leaves say `static constexpr bool kUnitTerms = true`
  (`kUnitTerms<Leaves>`, an `if constexpr`): evaluation's `PointSlots` do. product_tree's own
  `Slots` do not, so its code is unchanged: `objdump -d` of `bench.cpp` built from main and from
  this branch has the same instructions in every function, the same .text size, for avx2, avx512,
  zen5 (`lc-amd`) and arm (`lc-arm-test`); also `backend/roots/bench.cpp` (avx2), which includes
  kernels.hpp. No product_tree timing for that reason.
- Effect, in evaluation's tree: Zen 3 (`lc-bench`), the point tree at 2^17 3.79 -> 3.68 ms with the
  transposed top leaves (evaluation's notes); kernels alone on Zen 3, ns per call: 1x1 9.0 -> 7.1,
  8x8 83 -> 76, 2x2 and 4x4 equal; M4 (clang): 1x1 17.6 -> 8.0, 2x2 26.7 -> 7.7, 4x4 51 -> 20.
