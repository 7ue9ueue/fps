# #143 r1: power projection's column sums in one inverse each

2026-10-18, claude (issue #143, round 1, target all; the ntt side: `backend/ntt/notes/143-r1.md`).
Base: main d3fda99 (#233 merged). GCC 16.2 (pinned image), each target's flags.

## What changed

`ntt::Transform::inverse_product` takes 8 terms now, so `column_sum` runs the level T - 3 sums of
5 and 7 products (P's next columns p'_j = sum over a + b = 2j + 1 of p_a c_b) as one inverse each,
not 4 + 1 and 4 + 3 terms in two inverses and an `add_words`: 4 inverses where there were 6, as
lc-opt's `projection_last_levels`. `ProjectionColumns::tmp` (m/4 words, the second inverse's
output) is gone; it was the last array taken, so no other array moved.

The ntt side changes 2- to 4-product sums too (zmm: the sums with K a template argument instead
of the run-time loop; avx2: 3 products through `inverse_sum<3>` with the asm leaf product instead
of `bottom_leaves3_*`), which the composition runs at its column levels and in compose.

about 280 ms on Zen 3), so 0.996-1.000 is the size expected. Zen 3's geomean comes from the small
sizes (power projection 0.971-0.993 at n = 32 to 8192, `/6` to `/14`; a guess: its sums of 3
products, as ntt's `inverse_product3/8` ran 0.76 of main's).

power_projection 1.042, compositional_inverse 1.028, with `mul@ntt/10` (ntt::multiply, code

of main's (`terms13_lc-zen5.txt`, `terms14_lc-zen5.txt`); code placement (as #226), not the sums.
