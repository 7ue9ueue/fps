# #105 r1: move lc-opt's compose, power projection and compositional inverse

2026-10-12. Base `origin/main` cbb6d26 (rebased onto 99be240 before the pull request, which
changes docs only). New kernel `backend/composition`.

## What

- `compose`, `power_projection`, `compositional_inverse` on `ntt::Transform`'s public ops (no NTT
  internals but the 8 x 8 transposes and `Narrow` of `intrinsics.hpp`), every target.
  Algorithm and layout lc-opt's (notes.md, Design); not moved: pruned transforms, the fused
  bottoms, the one-dimensional levels 0, 1, T - 3, T - 2, power projection's doubling.
- Tests (`test.cpp`): compose and power projection against O(n^3) references at 0 .. 33, 63 ..
  65, 127 .. 129, 255 .. 257, 511 .. 513 and random sizes, three input kinds, f and g shorter and
  longer than n, g[0] != 0; compositional_inverse by compose(f, g) = x, up to 16389; at 2^10 ..
  2^17 compose against `series::exp(g)` and `series::inverse(1 - g)`, power projection by the
  transposition (sum a[k] f[k] = f(g)[n - 1]) and a closed form (g = x / (1 - x)); the leaf
  passes of every simd struct against Scalar, Scalar's Graeffe against its definition; 4
  threads; the length error. All 6 targets pass, -O2 and ASan/UBSan.
- The lc-opt harness: `~/Documents/hpc_library-explore/composition/issue105/` (`compare.cpp`
  with `--check`, `compare_parts.cpp` for per-step costs, `run_*.sh`; on `lc-bench` in
  `~/explore/hpc_library/composition/issue105/`).

## Attempts, `lc-bench` (Zen 3), same run as lc-opt, compose / power_projection at n = 2^17

| version | compose ms | power_projection ms | lc-opt ms |
|---|---:|---:|---:|
| frontend (#130) | 182.5 | - | 29.2 / 26.2 |
| 1: generic levels, a Montgomery product per term | 46.4 | 48.3 | 29.2 / 26.2 |
| 2: + 64-bit leaf sums (x86, Scalar) | per step only (below) | | |
| 3: + level T - 1 one-dimensional | 42.4 | 39.7 | 29.5 / 26.0 |

Per step at m = 2^17, us: Graeffe pass 412 -> 280 and projection pass 932 -> 582 with the
64-bit sums (version 2); the rest unchanged (notes.md). Versions 2 and 3 together: compose
46.4 -> 42.4 ms, power projection 48.3 -> 39.7. By the per-step times the leaf sums account for
about 2.1 ms (compose) and 5.6 ms (projection) of that over the 16 generic levels, the
one-dimensional level T - 1 (a cyclic product of m in place of a forward of 2m, the spread, an
inverse_product of 4m and the forward of Q_(T-1) at 4m) for the rest (a guess from the sums).

Final table (fps / lc-opt): compose 0.28 (lg 6), 0.62 (8), 1.41 (11), 1.44 (14), 1.46 (16),
1.44 (18); power_projection 1.50 / 1.51 / 1.53 at lg 11 / 14 / 18; compositional_inverse 1.39 /
1.46 / 1.48. Against the frontend's version: compose 4.2x faster at 2^17, 2.0x at n = 32.

Per target, `bench.cpp` (3 rounds), in units of `mul@ntt` of the same run: notes.md. Neoverse V2
runs the Montgomery-per-term leaf sums (no 64-bit sum path for Neon yet) and still lands at
42.4 units for compose/18, as Zen 3.
