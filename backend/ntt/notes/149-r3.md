# #149 r3: forward_h4 in the pruned tiles (for backend/composition)

2026-10-16, claude (issue #149, round 3, target all). One change to avx2.hpp, for the hooked
forwards `backend/composition` runs (its log: `backend/composition/notes/149-r3.md`). Base: main
e4f6e8b. GCC 16.2 (the pinned image), `-O2 -march=x86-64-v3`, `lc-bench` (EPYC 7B13, Zen 3).

## What

`forward_pruned_tiles` (avx2: `forward_hooked` and `forward_upper_hooked`) ran the tile's h = 4
level as one `kernels::forward` call per group of 16 vectors; #87 r2 had given `forward_levels`
(the plain forwards' tiles, and `truncate_blocks`' through `forward_tiles`) lc-opt's
`kernels::forward_h4`, one loop over the run's groups. The pruned tiles now run it too: h = 4 is
below `kPruneForward` (32), so those groups were always whole. The levels h >= 16 keep
`forward_group_pruned`. Nothing else calls these tiles (only the hooked ops, which only
backend/composition uses), so the ntt benches compile to the same code.

## Tests

`test_hooked.cpp` and `test_doubling.cpp` (rounds 1 and 2) check `forward_hooked` and
`forward_upper_hooked` against the scalar forward for every column bit, lg 6 .. 20, on every
variant; they pass on all six targets at -O2 and with ASan/UBSan.
