# #93 r1: short products depend on inlining and placement

2026-10-12, claude (issue #93, round 1): short products' speed against the program's code, Zen 3
(avx2 target, the asm variant). Numbers: Measurements, Zen 3 short products and code layout.
Probes, scripts and raw output: `~/Documents/hpc_library-explore/ntt/issue93/` (`src/`: `probe93.cpp`
with MIX, `build.sh`, `run.sh`, `summary.py`, `grid.py`, `variant.sh`, `trace.hpp`,
`footprint.py`, `correlate.py`; `place_pin.diff`: the code below; `lc-k68/results.tgz`). No ntt
code changed.
- Found: the spread has two causes, TU-dependent inlining of the COMDAT product functions and their
  placement in .text; data placement and the caller's position do not matter.
- Built and measured, not kept (`place_pin.diff`): every function of the avx2 product path (the
  API calls, `product`, `square`, the trees, bottoms, span levels, boundary functions and the
  generated kernels) with its inlining pinned and in a section `.text.sorted.fps.ntt.<key>`. GNU ld
  2.42/2.44's default script places `SORT(.text.sorted.*)` together at the start of .text, by name,
  so the keys fix the order whatever else the program holds; an empty `used` anchor function,
  64-byte aligned, sorts first. GCC refuses one section for a COMDAT function and a local IPA-SRA
  clone of a sibling instantiation ("section type conflict"), so each tagged function also needs
  `[[gnu::noclone]]`. Mach-O, clang and other linkers would need their own handling. It makes the
  speed program-independent but not fast: every fixed layout tried was 2-5% slower than main's
  median at 2^6-2^8 (geomean), and any change to the group re-rolls it.
- Leads for round 2: the mechanism (a PMU on Zen 3, #94; or `lc-intel`'s counters on the avx2
  build); smaller hot code at 2^6 (product/6 runs about 1600 distinct instructions once each: a
  pair of groups through `PairBottom`'s first and last kernels, 2 x 7.5 KB `product<Bottom>`
  copies); the same pinning for `intrinsics<S>` (Zen 5 2^9-2^12, #101), where a template's
  instantiations for Avx512Vl and Avx512 would share one section name.
