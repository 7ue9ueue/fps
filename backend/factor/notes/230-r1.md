## Finding

`rows_block`'s loop over columns (`combine_rows`: R = 4 rows, one vector; 18 instructions: `ld1r`,
3 `ldr s`, `ldr q`, 8 `umlal`/`umlal2`, the pointer and counter updates, `cmp`, `b.ne`) takes 76%
of the factor bench's samples. GCC emits the same 18 instructions with 15.2 and 16.2; 15.2 put the
loop at 12 mod 32, 16.2 at 0, and 16.2 ran factor/7 and factor/8 2.8% and 3.1% slower
(535 against 521 us, 3.30 against 3.21 ms; `ab-factor-f12.txt`). `-falign-loops=32` moves 15.2's
to 0 too: 1.027-1.030 there (sweep). The placement scan (all 8 word starts) has one more slow
start, +9-10% (`pscan-pass2-r1.txt`, factor and `frontend-bench_algebra`).

## Change

Neon (`Halves`): the loop on pointers (column, coefficient) and a count, a do-while after
`simd::align_loop<kRowsLoopNops>` (`backend/simd/align.hpp`), kRowsLoopNops = 0: the loop starts at
0 mod 32 with GCC 15.2 and 16.2 (objdump). The counter is now `subs` + `b.ne`: 17 instructions.
x86 and scalar run the old loop (bench binaries byte-identical to main's on scalar, sse, avx2,
avx512, zen5).

Scan of the new loop, 0..7 nops (`kscan-rows-16.2`, 3 interleaved runs, median): starts 0, 4, 8,
12, 16 within 0.4% of each other at factor/7 and factor/8, each 2.8-3.3% faster than main's binary;
5-7 nops (GCC pads those back to 0, so 5-7 more nops run per entry, every 17 columns): +0.6-1.2%.
So the new loop is fast at every start it can take, and k = 0 runs the fewest nops.
