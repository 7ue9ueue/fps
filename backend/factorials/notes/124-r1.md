# #124 r1: the lane grid for backend/taylor_shift

2026-10-13, claude (issue #124, round 1; the kernel's log: `backend/taylor_shift/notes/124-r1.md`).
Base: main 3fd62d5.

- `Chains::lanes(n, h, start, first, down)`: `run()`'s passes 1 and 2 (lane products, then the
  prefix and suffix products over the lanes and one inversion) as a public function, for kernels
  that run their own chains over the same lanes: start[s] = a_s = min(h + s c, n - c),
  first[s] = (a_s)!, down[s] = 1 / (a_s + c - 1)!, c = chunk(n). `Chains::Lanes` is public, and
  `Chains::invert(x)` exposes the binary extended Euclid inverse. The Taylor shift takes its i!,
  1 / k! and c^j / j! chains' starts from it (no table of (1024 k)! as lc-opt).
- A first version moved those lines out of `run()`, which then called `lanes()`: `kernel.py bench
  factorials --base` on `lc-bench` (Zen 3, 3 rounds) gave tables/8 1.119 (296 -> 330 ns), /10
  1.050, the rest 0.94-1.02 (gated geomean 1.0122). Code layout, as the Measurements section logs
  for small n. Now `lanes()` is a copy of `run()`'s first lines and `run()` is main's text, so the
  factorials and frontend binaries do not change.
- Tests: `test.cpp` and `test_no_tuner.cpp` unchanged, every target; `lanes()` is tested through
  `backend/taylor_shift`'s tests (every struct, K and step, against binomial sums).
