# 190 r1: the #183 workaround under GCC 15.3 and 16.2

2026-10-13, branch `agent/toolchain-all-r1` on main 1c59503. Overall decision: `backend/tune/notes/190-r1.md`.

The folds' loop over the terms carries `#pragma GCC novector` (`FPS_ROOTS_NOVECTOR`) because GCC 15.2
vectorizes it wrongly at -O2 with AVX2 for the `Scalar` struct (issue #183).

- Correctness without the pragma, `kernel.py test roots --target avx2 --sanitize` (-O2 only) on
  `lc-amd`: GCC 15.2.0 1951 checks, 109 failures (the `scalar/scalar` lines, as in #183); 15.3.0
  and 16.2.0 0 failures.
- Cost of the pragma, `kernel.py bench roots` (gated cases, 5 rounds), without it / with it, the same
  compiler on both sides: the bench binaries are byte-identical on `avx2` (`lc-bench`), `avx512`
  (`lc-intel`) and `zen5` (`lc-zen5`) with both 15.3 and 16.2, and on `arm` (`lc-arm`) with 16.2;
  `arm` with 15.3 differs, geomean 0.9999. The timed paths use vector `Sums`, where the pragma
  changes nothing; only the `Scalar` struct's loop is affected.

Kept: it protects users who build with GCC 15.2, and costs nothing measurable.
